## 해석과 권고

### 1. 쿼리 확장: 측정 가능한 이득이 없다 → 기본값을 끄는 것을 권고 (DECISION_LOG E-19)

- **세 실행 모두 신뢰구간이 0을 포함한다.** 이득이 있더라도 상한이 nDCG@10 +0.025 ~ +0.034 수준이다.

  | 실행 | Δ | 95% CI |
  |---|---:|---|
  | Haiku 4.5 run1 | +0.006 | [−0.014, +0.025] |
  | Haiku 4.5 run2 | +0.015 | [−0.003, +0.033] |
  | Sonnet 4.6 | +0.012 | [−0.010, +0.034] |

- **비결정적이다.** 같은 모델로 두 번 실행했을 때 확장 결과가 같은 질의는 7/91개뿐이고, 두 실행의 차이가 +0.009였다.
- **비용은 측정된다.** 캐시를 놓친 검색마다 다음 비용이 순차로 더해진다.
  - LLM 호출 1회, Haiku 4.5 기준 지연 p50 0.77s
  - 토큰 143/50, Haiku 4.5 기준 1천 검색당 약 $0.39
  - Bedrock 분당 요청 쿼터 50 중 일부 (A-13)
- **유형별로는 결론을 내리지 않는다.** semantic 질의에서 +0.026 [−0.007, +0.061]으로 가능성이 보이고, hard 질의는 run1에서 −0.022였다. 표본이 작아 판단을 보류한다.
- **재검토 조건**: 평가 v2(사람이 쓴 질의, 약 350개)에서 확장을 다시 비교한다. 그 전까지는 기능 플래그로 끈다.

### 2. 결과 설명 모델: Haiku 4.5를 권고하고, 설명은 응답 경로에서 분리한다 (A-14)

- **형식 유효성**: 두 모델 모두 20/20개가 정확히 10개 설명을 반환했다.
- **지연**: Haiku 4.5는 p50 1.78s, Sonnet 4.6은 p50 2.71s다. 다만 Haiku 4.5는 꼬리가 길다. 20개 중 4개가 6.7~9.0s였다(p95 8.90s, Sonnet은 3.29s). 원인은 확인하지 않았다. SDK 내부 재시도나 global 라우팅을 의심한다.
- **비용**: 1천 검색당 LLM 비용이 Haiku 4.5 $2.26, Sonnet 4.6 $6.94로 약 3배 차이다(확장과 설명 포함, 캐시 미적중 기준).
- **한계**: 설명의 **품질**은 평가하지 않았다(판정 기준·judge 없음). 형식 유효성, 지연, 비용만 비교했다.
- **권고**: 기본 모델은 Haiku 4.5로 한다. ACTIVE 상태이고, 3배 저렴하며, 중앙값 지연도 짧다. 설명 호출은 p50만으로도 검색 응답 시간의 대부분을 차지하고 꼬리 지연도 길다. 그래서 검색 결과를 먼저 반환하고 설명은 나중에 불러오는 구조로 바꾸는 것(C-08)이 모델 선택보다 효과가 크다.

### 3. 호환성

- `ConverseCommand`에 `temperature: 0.5`를 넣은 호출을 두 모델 모두 받아들였다. Slack 에이전트의 sampling 설정은 4.5/4.6 세대에서 수정할 필요가 없다.
- 5.x 세대는 Anthropic 문서상 기본값이 아닌 sampling 값을 거부한다. 계정 접근이 막혀 있어(A-12) 실측하지 못했다.
